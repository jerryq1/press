# RAGFlow 使用注意事项

## 一、账户与权限相关

### 1.1 超级管理员与普通用户的区别

| 角色 | 账号示例 | 如何产生 | 核心权限 |
|------|----------|----------|----------|
| **超级管理员** | `admin@ragflow.io` | 系统初始化时**自动创建** | 拥有系统最高权限 |
| **普通用户** | `316059946@qq.com` (mr.j) | 通过注册页面**自行注册** | 普通用户权限 |

> **我们实际遇到的情况**：你注册的 `316059946@qq.com` 账号不是超级管理员，真正的超级管理员是 `admin@ragflow.io`。你用 `mr.j` 账号直接访问 `/admin/users` 会报 `No authorization.` 错误。

### 1.2 密码相关

| 问题 | 说明 | 解决方案 |
|------|------|----------|
| **密码无法反向查找** | 密码是单向加密存储，无法从数据库反推出原始密码 | 只能重置，不能找回 |
| **换服务器后密码失效** | 用镜像恢复服务器后，原密码无法登录 | 需要重置密码 |
| **默认密码** | `admin@ragflow.io` 的默认密码是 `admin` | 首次登录后建议修改 |

### 1.3 重置密码的方法

**方法一：命令行重置（我们实际用过）**

```bash
sudo docker exec docker-ragflow-cpu-1 python3 -c "
import pymysql
from werkzeug.security import generate_password_hash
conn = pymysql.connect(host='mysql', user='root', password='infini_rag_flow', database='rag_flow')
cursor = conn.cursor()
new_password_hash = generate_password_hash('123456')
cursor.execute('UPDATE user SET password = %s WHERE email = %s', (new_password_hash, '316059946@qq.com'))
conn.commit()
print('密码已重置')
conn.close()
"
```

> **注意**：我们实际执行时，这个命令执行成功但登录仍然失败，说明哈希生成方式可能不匹配。

**方法二：通过管理员后台重置**

访问 `http://服务器IP/admin/users`，用 `admin@ragflow.io` 登录后，在用户列表中重置密码。

### 1.4 管理员后台入口

- **入口地址**：`http://服务器IP/admin/users`
- **说明**：这个入口在 UI 界面中没有显式菜单，需要直接通过 URL 访问
- **我们实际遇到的情况**：你用 `mr.j` 账号直接访问这个地址会报错，需要用 `admin` 账号登录

## 二、模型配置相关

### 2.1 新成员无法使用聊天功能

**问题现象**：新成员 `2865945025` 登录后，进入聊天页面报错 `TypeError: x.find is not a function`

**根本原因**：新账户没有配置任何聊天模型（LLM）

**解决方案（我们实际讨论过的）**：

1. 用 `admin` 账号帮新成员配置模型
2. 或让新成员自己配置：点击头像 → 模型提供商 → 添加模型

### 2.2 每个成员都需要自己配置模型吗？

- 是的，默认情况下每个成员需要自己配置模型
- 可以通过配置 `user_default_llm` 让新成员自动获得模型配置（我们没有实际验证过）

## 三、知识库与聊天助手共享相关

### 3.1 核心发现：助手权限继承知识库权限

**我们实际遇到的情况**：

- 你用 `316059946` 账号创建了聊天助手
- 将知识库共享给 `2865945025` 后，`2865945025` 能看到你创建的聊天助手
- 但 `2865945025` 无法使用这个助手

**原因分析**：
1. `2865945025` 能看到助手，是因为他有权访问该助手绑定的知识库
2. 无法使用，是因为他没有配置自己的聊天模型

### 3.2 知识库权限级别

我们讨论过的权限：
- 将知识库共享给成员
- 成员有知识库的读权限后，可以看到关联的聊天助手

### 3.3 共享助手却无法使用的原因

| 可能原因 | 说明 |
|----------|------|
| 成员没有配置聊天模型 | 这是我们实际遇到的问题 |
| 成员对知识库没有访问权限 | 如果有权限，就能看到助手 |

## 四、我们实际遇到的错误及解决方案

### 4.1 `TypeError: x.find is not a function`

| 原因 | 解决方案 |
|----------|----------|
| 新账户 `2865945025` 没有配置模型 | 配置聊天模型和嵌入模型 |
| 浏览器缓存问题 | 清除缓存或使用无痕模式 |

### 4.2 `No authorization.`

| 原因 | 解决方案 |
|----------|----------|
| 用非管理员账号访问 `/admin/users` | 用 `admin@ragflow.io` 登录后再访问 |

### 4.3 密码重置后仍无法登录

| 原因 | 说明 |
|----------|------|
| 哈希生成方式可能不匹配 | 命令行重置后登录失败，需要从 admin 后台重置 |

### 4.4 MySQL 登录失败

| 原因 | 解决方案 |
|----------|------|
| 密码错误 | 查看 `.env` 文件中的 `MYSQL_PASSWORD=infini_rag_flow` |

## 六、注意事项总结

1. **`admin@ragflow.io` 是唯一的超级管理员**，普通用户需要它来授权
2. **密码无法反查**，忘记只能重置
3. **用镜像恢复服务器后，原密码会失效**，需要重置
4. **管理员后台入口是 `/admin/users`**，需要直接用 URL 访问
5. **新成员需要自己配置聊天模型**，否则聊天功能会报错
6. **聊天助手是跟着知识库权限走的**：能看到助手 ≠ 能用助手
7. **命令行重置密码可能不生效**，用 admin 后台重置更可靠
