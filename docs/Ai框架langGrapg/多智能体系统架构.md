# 多智能体系统架构设计：从单体到网络化智能

## 一、开篇：为什么需要多智能体？

### 1.1 从“一个人”到“一个团队”

- **单智能体** = 一个人既当厨师又当服务员还管账，小摊贩可以，但规模大了必然崩溃
- **多智能体** = 团队：厨师做菜，服务员接待，收银员结账，每个人专注自己的领域

### 1.2 官方定义与通俗理解

| 维度 | 官方描述 | 生活比喻 |
|------|----------|----------|
| **单智能体** | 一个LLM实例负责所有决策，集成所有工具和逻辑 | 一个人包揽所有工作的“光杆司令” |
| **多智能体** | 多个LLM实例通过消息传递协作，每个专注特定领域 | 各司其职、互相配合的“专业团队” |

### 1.3 多智能体的核心价值（企业级）

1. **解耦复杂任务**：每个Agent只解决自己领域的问题
2. **可扩展性**：动态增加新Agent，不影响现有系统
3. **可控性**：支持人类干预闭环（HITL）、时间回溯

---

## 二、核心概念：MCP vs A2A vs Skills

### 2.1 两者定位的本质区别

| 协议 | 全称 | 解决的问题 | 类比 |
|------|------|------------|------|
| **MCP** | Model Context Protocol | 让AI连接外部数据源和工具 | AI的“USB接口”，标准化外设连接 |
| **A2A** | Agent-to-Agent Protocol | 让不同Agent之间互相通信协作 | Agent的“语言”，标准化团队沟通 |

> 💡 **一句话**：MCP解决“AI怎么用工具”，A2A解决“AI怎么和其他AI说话”

### 2.2 Agent Skills（智能体技能）

Skills是赋予Agent专业能力的方式，在LangGraph中体现为：
- 工具（Tools）：搜索引擎、计算器、API调用
- 子Agent：将其他Agent封装成可调用的“技能”

## 三、五种多智能体架构模式

### 3.1 Network（网络型）

**结构**：去中心化，每个Agent可与其他任意Agent通信

**场景**：头脑风暴、并行信息搜集

```python
# 三个并行研究Agent + 一个汇总Agent
workflow.add_node("policy", policy_agent)
workflow.add_node("tech", tech_agent)
workflow.add_node("competitor", competitor_agent)
workflow.add_node("synthesizer", synthesizer)

workflow.add_edge("policy", "synthesizer")
workflow.add_edge("tech", "synthesizer")
workflow.add_edge("competitor", "synthesizer")
```

### 3.2 Supervisor（监督者型）⭐⭐⭐⭐⭐

**结构**：一个主控Agent调度其他子Agent

**场景**：企业助手（IT/HR/财务）、智能客服路由

```python
from langgraph_supervisor import create_supervisor
from langchain.agents import create_agent  # 新版API

# 创建子Agent（使用新版create_agent）
flight_assistant = create_agent(
    model=model,
    tools=[book_flight],
    name="flight_assistant"
)

hotel_assistant = create_agent(
    model=model,
    tools=[book_hotel],
    name="hotel_assistant"
)

# 创建Supervisor
supervisor = create_supervisor(
    agents=[flight_assistant, hotel_assistant],
    model=model,
    prompt=(
        "你是旅行预订系统的调度主管。工作流程：\n"
        "1. 首先调用flight_assistant预订航班\n"
        "2. 然后调用hotel_assistant预订酒店\n"
        "3. 汇总结果并报告\n"
        "重要规则：每个助手只能调用一次，不要重复任何内容"
    ),
    output_mode="last_message",      # 只保留子Agent最后一条回复
    handoff_tool_name="transfer_to", # 自定义交接工具名
    supervisor_name="travel_supervisor"
).compile()
```

### 3.3 Supervisor as Tools（工具型监督者）

**结构**：将子Agent包装成工具，主LLM直接调用

**场景**：插件化架构、单一LLM核心+领域专家

```python
@tool
def legal_agent_tool(query: str) -> str:
    return legal_agent.invoke({"question": query})

main_agent = create_agent(
    model=model,
    tools=[legal_agent_tool, translation_agent_tool]
)
```

### 3.4 Hierarchical（层级型）

**结构**：多层Supervisor，类似公司组织架构

**场景**：大型项目管理、复杂管道任务

```python
# 第一层：子团队
market_team = create_supervisor([policy_agent, competitor_agent])
tech_team = create_supervisor([hardware_agent, software_agent])

# 第二层：顶层监督者
top_supervisor = create_supervisor([market_team, tech_team])
```

### 3.5 Custom（自定义混合型）

使用LangGraph的条件边灵活组合：

```python
def router(state) -> Literal["it_agent", "hr_agent", "parallel_group"]:
    intent = classify_intent(state["messages"][-1].content)
    return intent

workflow.add_conditional_edges("router", router)
```

## 四、两种核心协作机制：Supervisor vs Handoffs

这是LangGraph生态中实现Agent间协作的**两种根本不同的哲学**：

| 维度 | Supervisor模式 | Handoffs模式 |
|------|----------------|--------------|
| **一句话理解** | 有一个“经理”分配任务 | 员工自己决定转交给谁 |
| **控制方式** | 中央集权，Supervisor决定谁干活 | 民主协商，Agent主动交接 |
| **决策者** | 唯一的Supervisor Agent | 每个Agent都可以决定交接 |
| **上下文管理** | Supervisor持有全局上下文 | 交接时传递任务描述 |
| **适用场景** | 任务类型明确、需集中管控 | 自由对话、需自然流转 |
| **实现复杂度** | 低（一行代码创建） | 中（需手写Handoff工具） |

### 4.1 核心区别：一句话总结

| 模式 | 类比 |
|------|------|
| **Supervisor** | 餐厅经理：顾客点餐后，经理告诉厨师做什么、告诉服务员上什么 |
| **Handoffs** | 急诊室：护士处理不了就找医生，医生处理不了就找专家，自己决定交接 |

### 4.2 Supervisor模式（中央集权型）

**工作流程**：
1. Supervisor接收用户输入
2. Supervisor决定调用哪个子Agent
3. 子Agent执行并返回结果
4. Supervisor决定下一步（调用另一个Agent or 结束）

#### 4.2.1 流式输出与消息过滤

Supervisor会产生大量系统消息（如"Successfully transferred to..."），企业级应用必须过滤：

```python
import re

def filter_messages(chunk: dict) -> str:
    """过滤掉英文系统消息和重复内容，只保留中文业务输出"""
    output = ""
    
    if isinstance(chunk, dict):
        for role, payload in chunk.items():
            if isinstance(payload, dict) and "messages" in payload:
                for msg in payload["messages"]:
                    if hasattr(msg, 'content') and msg.content:
                        content = msg.content.strip()
                        
                        # 过滤英文系统消息
                        if (content and
                            not content.startswith("Successfully") and
                            not content.startswith("Transferring") and
                            "Successfully transferred" not in content):
                            
                            # 只保留中文内容
                            chinese_content = re.sub(r'[^\u4e00-\u9fff，。！？：；""、\s\d✅]', '', content)
                            if chinese_content and len(chinese_content.strip()) > 5:
                                output += f"{role}: {chinese_content.strip()}\n"
    
    return output

# 流式处理 + 去重
seen_contents = set()
for chunk in supervisor.stream(input_data):
    filtered_output = filter_messages(chunk)
    if filtered_output:
        for line in filtered_output.strip().split('\n'):
            if line and line not in seen_contents:
                print(line)
                seen_contents.add(line)
```

#### 4.2.2 调用次数控制

必须在Prompt中明确限制，防止Agent死循环：

```python
supervisor = create_supervisor(
    agents=[flight_assistant, hotel_assistant],
    model=model,
    prompt=(
        "重要规则：\n"
        "- 每个助手只能调用一次\n"      # 防止死循环
        "- 不要重复任何内容\n"
        "- 不要输出任何英文\n"
    )
)
```

#### 4.2.3 异常降级处理

Supervisor调用失败时，直接调用工具作为降级方案：

```python
try:
    for chunk in supervisor.stream(input_data):
        # 正常处理
        pass
except Exception as e:
    print(f"Supervisor处理失败: {e}，执行降级...")
    # 降级：直接调用工具
    flight_result = book_flight(from_airport, to_airport)
    hotel_result = book_hotel(hotel_name)
```

### 4.3 Handoffs模式（民主协商型）

**核心思想**：Agent主动将任务交接给其他Agent，而不是由中央调度员分配。

#### 4.3.1 Handoffs的两种实现方式

| 实现方式 | 工具 | 特点 | 适用场景 |
|----------|------|------|----------|
| **高层API** | `create_handoff_tool` from `langgraph_swarm` | 简单，自动处理状态 | 简单对话流转 |
| **底层实现** | `Command` + `Send` | 灵活，完全控制 | 企业级复杂任务交接 |

#### 4.3.2 底层实现：Command + Send（推荐）

```python
from typing import Annotated
from langchain_core.tools import tool
from langgraph.graph.message import MessagesState
from langgraph.prebuilt.tool_node import InjectedState
from langgraph.types import Command, Send

def create_handoff_tool(agent_name: str, description: str = None):
    """创建Handoff工具的工厂函数"""
    name = f"transfer_to_{agent_name}"
    desc = description or f"移交给{agent_name}"
    
    @tool(name, description=desc)
    def handoff_tool(
        task_description: Annotated[str, "描述下一个Agent要做什么"],
        state: Annotated[MessagesState, InjectedState],  # 自动注入当前状态
    ) -> Command:
        """将任务移交给指定Agent"""
        task_description_message = {
            "role": "user",
            "content": task_description,
        }
        agent_input = {
            **state,
            "messages": [task_description_message],
        }
        
        return Command(
            goto=[Send(agent_name, agent_input)],  # 跳转到指定Agent
            graph=Command.PARENT,                  # 在父图中执行
        )
    
    return handoff_tool
```

**关键概念解释**：

| 概念 | 作用 |
|------|------|
| `Command` | 控制图执行的指令，告诉系统下一步做什么 |
| `Send` | 指定下一个要执行的节点（Agent）和输入数据 |
| `InjectedState` | 依赖注入，让工具自动访问图的当前状态 |
| `graph=Command.PARENT` | 在多级图嵌套时，在当前图的父图中执行 |

#### 4.3.3 完整示例：航班+酒店预订系统

```python
import os
from typing import Annotated
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from langchain_core.tools import tool
from langchain.agents import create_agent
from langgraph.graph import StateGraph, START
from langgraph.graph.message import MessagesState
from langgraph.prebuilt.tool_node import InjectedState
from langgraph.types import Command, Send

# 1. 初始化模型
def init_llm_model() -> ChatOpenAI:
    return ChatOpenAI(
        model="qwen-plus",
        temperature=0.1,
        max_tokens=1024
    )

model = init_llm_model()

# 2. 业务工具（必须有docstring）
@tool("book_flight")
def book_flight(from_airport: str, to_airport: str) -> str:
    """预订航班，根据出发地和目的地完成机票预订"""
    return f"成功预订了从 {from_airport} 到 {to_airport} 的航班。"

@tool("book_hotel")
def book_hotel(hotel_name: str) -> str:
    """预订酒店，根据酒店名称完成预订"""
    return f"成功预订了 {hotel_name} 的住宿。"

# 3. 创建Handoff工具
transfer_to_flight_assistant = create_handoff_tool(
    agent_name="flight_assistant",
    description="将任务移交给航班预订助手",
)

transfer_to_hotel_assistant = create_handoff_tool(
    agent_name="hotel_assistant",
    description="将任务移交给酒店预订助手",
)

# 4. 创建Agent（互相包含对方的Handoff工具）
flight_assistant = create_agent(
    model=model,
    tools=[book_flight, transfer_to_hotel_assistant],  # 可以交接给酒店
    name="flight_assistant",
)

hotel_assistant = create_agent(
    model=model,
    tools=[book_hotel, transfer_to_flight_assistant],  # 可以交接回航班
    name="hotel_assistant",
)

# 5. 构建多Agent图
multi_agent_graph = (
    StateGraph(MessagesState)
    .add_node(flight_assistant)
    .add_node(hotel_assistant)
    .add_edge(START, "flight_assistant")  # 从航班助手开始
    .compile()
)

# 6. 运行
if __name__ == "__main__":
    result = multi_agent_graph.invoke({
        "messages": [HumanMessage(content="帮我预订从北京到上海的航班，并预订如家酒店")]
    })
    
    for msg in result["messages"]:
        if msg.type in ("human", "ai"):
            print(msg.content)
```

## 五、如何选择：Supervisor vs Handoffs

### 5.1 什么是“流程固定”？

**流程固定** = 任务的执行步骤是**预先确定的、可穷举的、顺序明确的**。

用三个问题判断：

| 问题 | 固定流程的回答 | 非固定流程的回答 |
|------|---------------|-----------------|
| 步骤顺序是确定的吗？ | 是，必须先A后B | 不一定，看情况 |
| 步骤数量是固定的吗？ | 是，就是N步 | 不一定，可能多可能少 |
| 可以画出确定的流程图吗？ | 是，一张图画完 | 否，有太多分支 |

### 5.2 固定流程 vs 非固定流程 示例

| 场景 | 流程特点 | 推荐 | 核心理由 |
|------|----------|------|----------|
| 请假审批（申请→主管→HR） | 固定 | Supervisor | 顺序固定，步骤固定 |
| 用户注册（手机→验证码→密码） | 固定 | Supervisor | 必须按顺序 |
| 订单支付（创建订单→扣库存→支付） | 固定 | Supervisor | 有严格依赖 |
| 数据ETL（抽取→清洗→加载） | 固定 | Supervisor | 流水线作业 |
| 客服对话（话题随时切换） | 不固定 | Handoffs | 用户不可预知 |
| 故障诊断（排查路径取决于发现） | 不固定 | Handoffs | 分支太多 |
| 旅游规划（机票/酒店/景点任意顺序） | 不固定 | Handoffs | 用户自由切换 |
| 问卷调查（有分支跳转） | 边界 | Supervisor+条件边 | 分支少用Supervisor |

### 5.3 判断流程图

```
                    ┌─────────────────┐
                    │  任务步骤是否固定？  │
                    └────────┬────────┘
                             │
              ┌──────────────┴──────────────┐
              │ 是                          │ 否
              ▼                             ▼
    ┌─────────────────┐           ┌─────────────────┐
    │ 是否需要并行执行？ │           │ 用户可能随时切换话题？│
    └────────┬────────┘           └────────┬────────┘
             │                              │
      ┌──────┴──────┐                 ┌──────┴──────┐
      │ 是         │ 否              │ 是         │ 否
      ▼            ▼                 ▼            ▼
┌──────────┐  ┌──────────┐     ┌──────────┐  ┌──────────┐
│Supervisor│  │Supervisor│     │ Handoffs │  │  都可以  │
│ (并行)   │  │ (顺序)   │     │          │  │ 看偏好  │
└──────────┘  └──────────┘     └──────────┘  └──────────┘
```

### 5.4 终极判断法：问一个关键问题

> **“用户能不能完全不按顺序操作？”**

| 回答 | 判断 | 推荐 |
|------|------|------|
| “不能，必须按顺序来” | 固定 | **Supervisor** |
| “能，用户想先做什么都行” | 不固定 | **Handoffs** |
| “理论上按顺序，但用户可能...” | 边界 | **先用Supervisor，再加Handoffs兜底** |

### 5.5 实战对照表

| 真实业务场景 | 推荐方案 | 核心理由 |
|-------------|----------|----------|
| 请假审批 | Supervisor | 流程固定，有顺序依赖 |
| 客服转接 | Handoffs | 用户话题不可预知 |
| 旅行预订 | 都可 | 固定顺序用Supervisor，灵活顺序用Handoffs |
| 表单填写（多字段收集） | Handoffs | 用户不按顺序提供信息 |
| 市场分析报告 | Supervisor | 需要并行收集信息 |
| 代码生成+审查+修改 | Supervisor | 需要循环和重试 |
| 智能家居控制 | Handoffs | 用户可以任意顺序下指令 |
| 故障诊断 | Handoffs | 排查路径取决于之前的发现 |

### 5.6 一句话选型

> **流程固定、步骤可预知 → Supervisor**
> **用户主导、话题会切换 → Handoffs**
> **不确定 → 先用Supervisor，发现瓶颈再改Handoffs**

## 六、企业级应用场景与模式组合

### 6.1 场景模式选型

| 场景 | 推荐架构 | 核心原因 |
|------|----------|----------|
| 智能客服（多部门） | Supervisor + 路由型 | 明确分工，易于扩展 |
| 研究报告生成 | 层级型 + 协作型 | 多团队协作，需汇总 |
| 代码审查助手 | 辩论型（Proposer+Critic） | 多轮校验提高质量 |
| 风险审批系统 | 人机混合（HITL）+ 分阶段 | 高风险需人工确认 |
| 多步骤预订系统 | Handoffs模式 | 自然流转，Agent间交接 |

### 6.2 企业内部AI助手完整示例

```python
class EnterpriseAssistant:
    """
    组合多种模式：
    - 路由型：意图识别分发
    - 协作型：IT问题并行查询
    - 人机混合：敏感操作需审批
    - 流式过滤：去除系统噪音
    """
    
    def build_workflow(self):
        workflow = StateGraph(EnterpriseState)
        
        workflow.add_node("router", self.intent_router)
        workflow.add_node("it_agent", self.it_handler)
        workflow.add_node("hr_agent", self.hr_handler)
        workflow.add_node("human_approval", self.approval_gate)
        
        workflow.add_conditional_edges("router", self.route_by_intent)
        return workflow.compile()
    
    def stream_with_filter(self, input_data):
        """流式输出 + 消息过滤 + 去重"""
        seen = set()
        for chunk in self.app.stream(input_data):
            filtered = self.filter_messages(chunk)
            if filtered:
                for line in filtered.strip().split('\n'):
                    if line and line not in seen:
                        yield line
                        seen.add(line)
```

## 七、最佳实践与企业级检查清单

### 7.1 何时使用多智能体？

✅ **适合**：任务可自然拆分、需要不同角色视角、已有明确分工流程

❌ **不必**：简单问答、任务强耦合、对延迟要求极高

### 7.2 企业级检查清单

| 检查项 | 说明 | 实现方式 |
|--------|------|----------|
| **消息过滤** | 过滤英文系统消息 | `filter_messages()`函数 |
| **去重处理** | 避免重复输出 | `seen_contents`集合 |
| **调用次数限制** | 防止死循环 | Prompt中明确限制 |
| **异常降级** | Supervisor失败时兜底 | try-except + 直接调用工具 |
| **输入验证** | 防止空输入 | `while not input`循环 |
| **流式输出** | 实时返回结果 | `supervisor.stream()` |
| **可观测性** | 追踪执行路径 | LangSmith集成 |

### 7.3 常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| Agent“忘记”对话 | 未配置checkpointer | 添加`InMemorySaver` |
| Token消耗过高 | 消息历史无限累积 | 设置`output_mode="last_message"` |
| 路由决策错误 | Supervisor指令不明确 | 优化prompt，给出具体规则 |
| 死循环 | 未限制调用次数 | Prompt中加"每个助手只能调用一次" |
| 输出大量英文 | 系统消息未过滤 | 实现`filter_messages()` |
| 重复输出 | 流式chunk重复 | 使用`seen_contents`去重 |

### 7.4 API版本说明

| 函数 | 来源 | 状态 |
|------|------|------|
| `create_react_agent` | `langgraph.prebuilt` | 旧版API，仍可用 |
| `create_agent` | `langchain.agents` | **新版推荐**，与LangChain生态统一 |

```python
# 旧版
from langgraph.prebuilt import create_react_agent
agent = create_react_agent(model, tools=[...], prompt="...")

# 新版（推荐）
from langchain.agents import create_agent
agent = create_agent(model, tools=[...], name="agent_name")
# 注意：新版不再显式接收prompt，通过tool schema和name传递
```

## 八、总结

### 8.1 决策树（完整版）

```
用户问题
    │
    ▼
任务步骤是否固定？
    │
    ├── 是（步骤确定、顺序明确）
    │        │
    │        ├── 需要并行执行？──→ Supervisor（并行）
    │        │
    │        ├── 需要循环/重试？──→ Supervisor（条件边）
    │        │
    │        └── 顺序执行 ──→ Supervisor（顺序）
    │
    └── 否（用户主导、话题会切换）
             │
             ├── 简单流转 ──→ Handoffs（高层API）
             │
             └── 复杂任务交接 ──→ Handoffs（Command+Send底层）
```

### 8.2 核心要点回顾

1. **多智能体架构**不是“用更多的Agent”，而是**用合适的协作机制解决合适的问题**

2. **流程固定用Supervisor**：你可以提前写出完整的执行顺序，不需要Agent做决策
    - 例子：请假审批、用户注册、订单支付

3. **流程不固定用Handoffs**：你写不出来，必须让Agent自己判断下一步做什么
    - 例子：客服对话、故障诊断、旅游规划

4. **企业级应用必须处理**：消息过滤、调用次数限制、异常降级、输入验证

5. **不确定时**：先用Supervisor，发现瓶颈再改Handoffs

### 8.3 最终建议

| 阶段 | 建议 |
|------|------|
| **MVP/原型** | 用Supervisor快速实现 |
| **用户量增长** | 观察用户行为，识别频繁转接场景 |
| **优化迭代** | 将高频转接场景改为Handoffs |
| **成熟系统** | Supervisor（主线流程）+ Handoffs（灵活交互）混合 |
