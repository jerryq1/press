# 埋堆堆网络标准化

## 一、为啥要做网络标准化建设
为应对埋堆堆日益业务快速增长，公司以容器化、微服务化、运维自动化为新一轮技术浪潮得到大力的发展，新技术的发展对网络建设要求越来越高；前期的网络规划以业务导向为主，为应对业务快速上下线，服务资源随需放置，“那里有资源就往那里放”的管理方式无法满足现业务快速增长需求。现有网络环境存在以下问题：
### 1.1、网络规划较为混乱、正式、测试、运维、灰度等环境全都混杂在一起，无网络边界，不便于管理和环境安全规则隔离；
![alt text](/yw/image.png)
### 1.2、业务单区域部署，对区域有强依赖性，单一区域出问题容易导致业务受损，出现问题只能等，业务系统不具备冗余性，稳定性无法保障；
![alt text](/yw/image-1.png)
### 1.3、资源从申请到交付无从下手，这个资源归属那个网络？要关联那个安全组？都蒙圈了……
![alt text](/yw/image-3.png)
## 二、标准化指导思想和实施
 以”安全为主，标准先行“为核心指导思想，通过网络标准化改造，规范各业务系统归属子网、设定网络边界安全策略和利用标准化改造去推动业务架构升级，为后续进行资源申请、子网分配、管理提供统一标准规范，并在此基础上进一步提升业务系统安全和稳定性。新架构下的网络标准化，具有以下特征：
### 2.1、业务网络标准化，资源归属规范化
![alt text](/yw/image-4.png)
>通过申请资源识别是归属WEB、DB或者K8S等资源，按规划放到相应的子网网段。从此妈妈再也不用担心我申请的资源放在那个网段，使用那个安全组，别人乱访问我了
### 2.2、规范统一出入口，各环境对外出口使用不同IP，相互隔离，互不影响，提升系统安全性和可维护性
![alt text](/yw/image-5.png)
>服务器只保留内网，去除外网IP，增加NAT网关，解决入口太多容易向公网暴露难管理问题，隔绝非法网请求。
>入口1（内网接入）：运维、开发、运营通过VPN统一接入，访问腾讯云内网开放管理后台、支付后台、发布系统等内部系统
>入口2（CLB\WAF）：用户访问各大业务系统，通过公网LB转发，域名不再解析服务器外网IP,减少暴露安全风险
>出口（安全网关）：业务系统主动对外请求统一通过NAT安全网关过滤（非法访问、异常流量等），服务器外网出口IP固定，增加服务器不再要向合作方加IP白名单，跟白名单say goodbye
### 2.3、烟囱式架构，服务不再受单点或单区域故障影响
![alt text](/yw/image-6.png)
### 2.4、打通云上云下内网环境，提高工作效率
![alt text](/yw/image-7.png)
>办公访问腾讯云线上环境，不再开放公网白名单，直接通过内网访问，大大提高工作效率
### 2.5、规范资源命名标识
cvm主机：环境(prod\test\yc\gray\public)-归属(server\ott\bigdata\yunwei)-服务名{01、02}
vpc子网：MDD正式环境-WEB-四区
安全组：MDD正式环境-基础安全组、测试环境-基础安全组、运维环境-基础安全组
### 2.6、规划网络安全组边界规则
![alt text](/yw/image-8.png)
>做好网络边界，限制那些IP可以访问，那些IP不能访问
