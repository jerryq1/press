# TypeScript 模块与命名空间详解

TypeScript 遵循 ES6 的模块化标准，同时也提供了命名空间（Namespace）作为较老版本的代码隔离方案。

## 1. ES6 模块：import / export

任何包含顶层 `import` 或 `export` 的文件都被视为一个模块。反之，如果没有这些，文件内容就属于全局命名空间。

```typescript
// math.ts
export const pi = 3.14159;
export function add(a: number, b: number) { return a + b; }

// app.ts
import { pi, add } from "./math";

console.log(pi);
console.log(add(1, 2));
```

---

## 2. 模块解析 (Module Resolution)

这是编译器用来弄清楚 `import` 引用指向哪个文件的过程。主要有两种策略：

| 策略 | 描述 |
| :--- | :--- |
| **Classic** | 默认在非 ES6 模块项目中使用，简单的向父目录查找同名文件。 |
| **Node** | 模拟 Node.js 的解析逻辑，支持查找 `node_modules` 和 `index.ts`。 |

在 `tsconfig.json` 中配置：
```json
{
  "compilerOptions": {
    "moduleResolution": "node"
  }
}
```

---

## 3. 命名空间 (Namespace)

用于在全局作用域内组织代码，防止命名污染。它通常用于编写老旧的库声明文件。

```typescript
namespace Validation {
    export interface StringValidator {
        isAcceptable(s: string): boolean;
    }

    export const lettersRegexp = /^[A-Za-z]+$/;
    export class LettersOnlyValidator implements StringValidator {
        isAcceptable(s: string) {
            return lettersRegexp.test(s);
        }
    }
}

// 使用
let validator = new Validation.LettersOnlyValidator();
```

---

**【面试口白】**：
> "在现代 TypeScript 开发中，我们绝大部分时间都在用 **ES6 模块**，因为它是原生标准且能支持 Tree Shaking。**命名空间**（Namespace）通常只在编写复杂的全局声明文件或处理非模块化的老代码时才会用到。
>
> 另外，理解 **模块解析策略** 很重要，特别是在配置 `baseUrl` 或 `paths` 别名时，只有设置正确的 `moduleResolution`（通常是 `node`），编译器才能正确映射到我们的业务逻辑文件。"
