# TypeScript 代码规范和检查详解

现代前端开发离不开代码质量的自动化保障体系。在 TypeScript 生态中，这主要依赖于一系列协同工作的工具链。

## 1. ESLint + TypeScript: 静态代码检查

ESLint 主要通过不同的插件来支持 TypeScript 项目。

- **`@typescript-eslint/parser`**：ESLint 的解析器，允许 ESLint 静态解析 TS 代码。
- **`@typescript-eslint/eslint-plugin`**：包含专门针对 TS 的 Linting 规则（如禁止使用 `any`，确保变量命名规范等）。

```javascript
// .eslintrc.js 示例
module.exports = {
  parser: '@typescript-eslint/parser',
  plugins: ['@typescript-eslint'],
  extends: [
    'eslint:recommended',
    'plugin:@typescript-eslint/recommended',
  ],
};
```

---

## 2. Prettier: 代码格式化

Prettier 专注于代码风格（如分号、引号、行宽），不关注逻辑。它与 ESLint 配合使用。

- **`eslint-config-prettier`**：关闭 ESLint 冲突的所有规则。
- **`eslint-plugin-prettier`**：让 Prettier 作为一条 ESLint 规则执行。

---

## 3. Husky + lint-staged: 提交阶段的自动化门禁

这一对组合用来在 `git commit` 时拦截并校验代码。

- **`Husky`**：用来创建 Git 钩子（如 `pre-commit`）。
- **`lint-staged`**：仅对本地暂存区（staged files）的文件运行检查，防止重新检查整个项目，从而提高效率。

---

## 4. 自动化流程示意图

```text
git commit 
   --> Husky 触发 pre-commit 钩子
      --> lint-staged 收集待提交文件
         --> 执行 eslint --fix (自动修复)
         --> 执行 prettier --write (格式化)
   --> 校验通过，提交成功
```

---

**【面试口白】**：
> "在多人协作的大型项目中，单纯依赖口头规范是不现实的。我们通常会搭建一套由 **ESLint (负责逻辑合规)**、**Prettier (负责代码风格一致性)**、以及 **Husky + lint-staged (负责强制执行门禁)** 组成的防御体系。
>
> 它的好处显而易见：开发者不需要为了简单的缩写或分号在 Code Review 时浪费时间。通过将这些工作前置到本地提交阶段，我们可以确保代码库里的每一行代码都是符合标准、格式统一的。"
